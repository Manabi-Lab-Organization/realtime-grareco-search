# 立ち上げ方と設定

自分たちのサーバに Realtime GraReco & Search を立ち上げ、使い始めるまでの手順です。

## 用意するもの

- **サーバ**：Docker と Docker Compose が動く Linux のサーバ。2CPU・メモリ4GB 程度が目安です
- **ドメイン名**：利用者が開くアドレス（例：`grareco.example.com`）。サーバを指すように DNS を設定しておきます
- **API キー**：ElevenLabs と Anthropic は必須。Gemini・OpenAI・Resend は任意（次の節）
- **アプリ**：文字起こしは、デスクトップアプリ（Mac / Windows）か iPhone アプリで行います。ブラウザだけでは文字起こしはできません（「アプリを入れる」の節）

## API キーの取り方

| サービス | 取る場所 | 使う機能 | `.env` の項目 |
|---|---|---|---|
| ElevenLabs（必須） | https://elevenlabs.io の設定画面の API キー | 文字起こし | `ELEVENLABS_API_KEY` |
| Anthropic（必須） | https://console.anthropic.com の API キー | リアルタイム調査・グラレコの区切りの判定・アシスタント。Gemini が無いときは要約・議事録なども | `ANTHROPIC_API_KEY` |
| Google Gemini（任意） | https://aistudio.google.com の API キー | 要約・議事録・用語解説・画像の読み取り・自動グラレコ・グラレコ検索 | `GEMINI_API_KEY` |
| OpenAI（任意） | https://platform.openai.com の API キー | 手動グラレコ・最終グラレコの作画 | `OPENAI_API_KEY` |
| Resend（任意） | https://resend.com の API キー | メール | `RESEND_API_KEY` |

- **Gemini は、請求先（Google Cloud の請求先アカウント）を紐づけた有料枠のキーを使ってください。** 無料枠のキーでは、送った内容が Google のサービス改善に使われ、人が読むこともあります
- どのサービスも、料金は各社がそのサービスに直接支払います。使いすぎを防ぐため、各サービスの管理画面で利用の上限を決めておくと安心です
- Gemini が無いときは、要約・議事録・用語解説・画像の読み取りは Anthropic が代わりに受け持ちます。自動グラレコとグラレコ検索は使えません
- Gemini のキーがあると、**自動グラレコは最初からオン**です。会議中、話の区切りごとにグラレコの画像を作ります（1 時間に最大 6 枚。1 枚ごとに画像の料金がかかります）。止めたい人は、会議の画面の設定で自動グラレコをオフにできます。1 時間あたりの枚数も変えられます
- Gemini と OpenAI のどちらも無いときは、グラレコは使えません

## `.env` を書く

リポジトリを取得して、見本から `.env` を作ります。

```sh
git clone https://github.com/Manabi-Lab-Organization/realtime-grareco-search.git
cd realtime-grareco-search
cp .env.example .env
```

必須の項目は次のとおりです。全項目の説明は [.env.example](../.env.example) にあります。

| 項目 | 書くこと |
|---|---|
| `APP_URL` | 利用者が開くアドレス。`https://grareco.example.com` のように https から書く。末尾に `/` は付けない |
| `SESSION_SECRET` | `openssl rand -hex 32` の結果 |
| `POSTGRES_PASSWORD` | `openssl rand -hex 24` の結果。**英数字だけにする。最初に立ち上げたあとは変えない** |
| `INITIAL_ADMIN_EMAIL` | 最初の管理者になる人のメールアドレス |
| `ELEVENLABS_API_KEY` | ElevenLabs のキー |
| `ANTHROPIC_API_KEY` | Anthropic のキー |

- `POSTGRES_PASSWORD` はデータベースを最初に作るときに使われます。あとで書き換えると、アプリがデータベースに繋がらなくなります
- 記号を含むパスワードは、データベースの接続先の指定の中で正しく読めなくなることがあります。英数字だけにしてください
- `.env` はほかの人が読めないようにしておきます（例：`chmod 600 .env`）

## 立ち上げる

入り口（https）をどう用意するかで、A と B のどちらかを選びます。

### A. このリポジトリの入り口を使う（おすすめ）

入り口として Caddy を一緒に立ち上げ、https の証明書を自動で取ります。

1. `.env` に `DOMAIN` を書きます（例：`DOMAIN=grareco.example.com`）。`APP_URL` は `https://` + `DOMAIN` にします
2. サーバの 80 番と 443 番のポートを外から届くようにします（証明書を取るときに使います）
3. 立ち上げます

```sh
docker compose --profile https up -d
```

`DOMAIN` を書き忘れると、入り口（caddy）が「.env に DOMAIN を設定してください」と出して止まります。

### B. すでにある入り口を使う

nginx などの入り口がすでにある場合は、アプリだけを立ち上げ、入り口から `127.0.0.1:3000` へ転送します。

```sh
docker compose up -d
```

nginx の設定例です（https の証明書の設定は省いています）。

```nginx
server {
    listen 443 ssl;
    server_name grareco.example.com;

    client_max_body_size 50m;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 3600s;
    }
}
```

- `X-Forwarded-Proto` が無いと、ログインしてもすぐにログイン画面に戻されます
- `Upgrade` と `Connection` が無いと、アプリからの文字起こし（常時接続）が繋がりません
- `client_max_body_size` は、補足資料の画像やカメラ観察の画像を受け取るためです（アプリ側の上限は 50MB）
- 入り口が別のサーバにあるときは、`.env` に `APP_BIND=0.0.0.0` を書き、3000 番のポートには入り口のサーバからだけ届くようにファイアウォールで絞ります
- 入り口が 2 段（例：外側の負荷分散と、その内側の nginx）になっているときは、`.env` に `TRUST_PROXY=2` を書きます

### http で直接開く場合（おすすめしません）

組織のネットワークの中だけで試すときなど、入り口を置かずに http で開くこともできます。通信が暗号化されないため、おすすめしません。

```
APP_URL=http://<サーバのIPアドレス>:3000
APP_BIND=0.0.0.0
ALLOW_HTTP=true
TRUST_PROXY=false
```

- `APP_URL` も `http://…:3000` にします
- デスクトップアプリと iPhone アプリは、http のアドレスには組織の中のネットワークのアドレス（`10.`・`172.16.`〜`172.31.`・`192.168.` で始まるもの、`localhost`、`.local` で終わる名前）でしか繋ぎません

## 立ち上がったか確かめる

```sh
docker compose ps
docker compose logs -f app
```

- `[Startup] 必須の設定はそろっています。` と `Server running on` が出ていれば立ち上がっています
- 必須の設定が足りないと、`[Startup] 必須の設定が足りないため、起動を止めます。` のあとに足りない項目の名前が出て、アプリが止まっては立ち上がり直すのを繰り返します。`.env` を直してから `docker compose up -d` をやり直してください
- `[DB] ensureTables failed` が出るときは、データベースに繋がっていません。`POSTGRES_PASSWORD` を最初から変えていないか、記号が入っていないかを確かめます
- `[Features]` の行に、キーが無くて使えない機能が出ます
- サーバの中から `curl http://127.0.0.1:3000/api/server-info` を開くと、版の情報が返ります

## 最初の管理者

1. サーバのログから、初期設定コードを探します。まだ管理者がいないあいだは、立ち上がるたびに `[Setup] 初期設定コード:` の行にコードが出ます

   ```sh
   docker compose logs app | grep 初期設定コード
   ```

2. ブラウザで `APP_URL` を開き、登録画面に進みます
3. `INITIAL_ADMIN_EMAIL` に書いたメールアドレスと、1 で探した初期設定コードを入れて登録します（Google ログインで登録するときも、先にコードを入れます）。このアドレスとコードがそろったときだけ、最初の 1 人として登録でき、管理者になります
4. 右上のメニューから管理画面（`/admin`）を開き、「利用状況」で使える機能を確かめます

- 初期設定コードは一度だけ使えます。サーバを立ち上げ直すと、新しいコードに変わります
- コードはサーバのログにだけ出ます。外から登録画面を開いた人には分からないので、メールアドレスを知られても管理者を横取りされません
- 最初の管理者は、ウェブ画面で登録します。デスクトップアプリや iPhone アプリからは作れません
- `INITIAL_ADMIN_EMAIL` を書き間違えたときは、`.env` を直して `docker compose up -d` をやり直します

## 利用者を招待する

2 人目からは、管理者の招待が要ります。

1. 管理画面の「招待」で、招待のリンクを作ります
   - **1人用**：1 回だけ使えます
   - **まとめて配る用**：何人でも使えます。使える日数を決めておくこともできます
2. リンクをメールやチャットで送ります。開いた人は、招待コードが入った状態で登録画面を開けます

## パスワードを忘れた人がいたら

- メール（Resend）を設定していれば、ログイン画面の「パスワードをお忘れですか？」から再設定のメールが届きます
- メールを設定していないときは、管理画面の「利用者」で鍵のボタンを押して一時パスワードを出し、本人に伝えます。一時パスワードは画面を閉じると二度と表示されません。本人にはログイン後にマイページでパスワードを変えてもらいます

## アプリを入れる

文字起こしは、デスクトップアプリか iPhone アプリで行います。

- **デスクトップアプリ（Mac / Windows）**：サーバの `/download`（ログインしてから開く）か、GitHub の Releases ページから入手します。`/download` は、公開されている最新の版をそのまま案内します（設定は要りません）
- **iPhone アプリ**：App Store で配る予定です。まだ公開していません

アプリを最初に開いたら、接続先のサーバのアドレス（`APP_URL`）を入れてからログインします。Mac では、マイク・画面収録（オンライン会議の音声を拾うため）の許可を求められます。

GitHub の Releases にデスクトップアプリがまだ出ていないあいだは、`/download` に「ダウンロードの準備中です」と出て、文字起こしはできません。Releases に出るまでお待ちください。

### 利用者への案内

アプリを使う人には、次の文をそのまま送れます。`https://grareco.example.com` は自社の `APP_URL` に、招待のリンクは管理画面の「招待」で作ったものに置き換えてください。

```text
会議の文字起こしと要約のアプリを使えるようにしました。次の順に準備してください。

1. 招待のリンクを開いて、アカウントを作ります
   （招待のリンク）
2. ブラウザで https://grareco.example.com/download を開き（ログインが要ります）、
   Mac か Windows のアプリを入れます
3. アプリを最初に開いたら、サーバのアドレスに https://grareco.example.com を入れて、
   作ったアカウントでログインします
4. Mac では、マイクと画面収録の許可を求められます。
   「システム設定」の「プライバシーとセキュリティ」で、このアプリを許可してください
   （画面収録は、オンライン会議の相手の声を拾うために使います）

使い方：https://grareco.example.com/guide
困ったとき：https://grareco.example.com/troubleshooting

会議で使うときは、冒頭で参加者に、文字起こしと AI での処理をすることを伝えてください。
```

`/guide`（使い方）と `/troubleshooting`（よくある質問）は、ログインしなくても開けます。

### ほかの参加者に知らせる

文字起こしでは、会議の参加者全員の声（オンライン会議の相手の声も含む）を拾い、音声と文字を外部の AI サービス（ElevenLabs・Anthropic など。「外部に送るデータ」の節）に送ります。会議の冒頭で、参加者に伝えてください。

文例：

> この会議は、記録のためにアプリで文字起こしをして、AI で要約を作ります。音声と文字は外部の AI サービスで処理されます。差し支えがあれば、今おっしゃってください。

社外の人が入る会議や、録音に同意しない人がいる会議では、使うかどうかを各社の決まりに沿って判断してください。

## 任意の設定

### メール

`RESEND_API_KEY` と `FROM_EMAIL` を書きます。`FROM_EMAIL` は、Resend で確認済みのドメインのアドレスにします。設定すると、パスワード再設定のメールと、会議が終わったあとの議事録のメールを送ります。

- メールの送信は Resend だけに対応しています。自社で用意したメールサーバ（SMTP）や、ほかのメール配信サービスは使えません
- 「ドメインの確認」とは、Resend の画面に出る DNS のレコード（SPF・DKIM など）を、自社のドメインの DNS に書き足す作業です。DNS を管理している人に頼んでください
- Resend にも料金（無料の範囲と上限）があります。Resend の画面で確かめてください
- メールを設定しなくても使えます。そのときは、パスワードを忘れた人に管理者が一時パスワードを出します

### Google ログイン

1. https://console.cloud.google.com で OAuth クライアント ID（種類はウェブアプリケーション）を作ります
2. 「承認済みの JavaScript 生成元」に `APP_URL` を入れます
3. `.env` に `GOOGLE_CLIENT_ID` を書きます。Google ログインが使えるのはウェブ画面とデスクトップアプリです。iPhone アプリはメールアドレスとパスワードでログインします

使えるメールアドレスのドメインは制限していません。Google ログインでも、新しく使い始める人には招待が要ります。

### 会社ごとの表示

| 項目 | 変わるところ |
|---|---|
| `APP_NAME` | ウェブ画面に出るアプリの名前（ヘッダー・ログイン画面・使い方のページ・共有ページなど）と、パスワード再設定のメールの件名。デスクトップアプリと iPhone アプリの名前は変わりません |
| `ORGANIZATION_NAME` | ウェブ画面の下に出る組織の名前 |
| `SUPPORT_EMAIL` | 困ったときのページに出す問い合わせ先 |
| `TERMS_URL`・`PRIVACY_URL` | 利用規約とプライバシーポリシーへのリンク。ウェブ画面とアプリに出ます |

### 会議室のカメラ観察

`ROOM_OBSERVATION_ENABLED=true` のときだけ動きます。使う前に [room-observation.md](room-observation.md) を読んでください。

### 会議中のアシスタント（試験的）

`ENABLE_NL_AGENT=true` のときだけ動きます。会議の画面で、言葉で頼むと、調査カードや要約のコピー、リアルタイム調査や自動グラレコの切り替えなどを代わりに行います。Anthropic のキーを使います。試験的な機能なので、思いどおりに動かないことがあります。

### そのほかの設定

`.env.example` に、すべての項目と説明があります。主なものは次のとおりです。

| 項目 | 内容 |
|---|---|
| `RESEARCH_ENABLED` | `false` にすると、リアルタイム調査を止めます |
| `RESEARCH_ORCHESTRATOR_MODEL` など | リアルタイム調査で使うモデル。下の「リアルタイム調査のモデル」を見てください |
| `GRARECO_MANUAL_PROVIDER` | `gemini` にすると、OpenAI のキーがあっても手動グラレコを Gemini で描きます |
| `GRARECO_WEBP_QUALITY` | グラレコの画像を保存する前に WebP にして軽くするときの品質（1〜100、既定 85）。`0` にすると変換せず、描いたままの形式で保存します。会議の終わりのメールには JPEG で添付し、画面からのダウンロードは PNG で渡します |
| `OPS_EMAIL` | グラレコの作画が OpenAI から Gemini に切り替わったときに知らせる先のアドレス（メールの設定が要ります） |
| `AUDIT_R2_*` | 4つそろえると、操作の記録を 1日ごとに Cloudflare R2 へ書き出します |
| `WEB_SESSION_*`・`TOKEN_*` など | 自動でログアウトするまでの時間などの細かい調整。ふつうは空のままにします |

### リアルタイム調査のモデル

ふつうは空のまま（既定のまま）でかまいません。費用や調査の質を比べたいときだけ変えます。

| 項目 | 内容 | 空のとき |
|---|---|---|
| `RESEARCH_ORCHESTRATOR_MODEL` | 会議を聞いて、何を調べるかを決める統括役のモデル | `claude-sonnet-5-5` |
| `RESEARCH_FACTCHECK_MODEL` | 数値や主張を確かめる調査役のモデル | `claude-sonnet-5-5` |
| `RESEARCH_HAIKU_MODEL` | そのほかの調査役（補足情報・論理課題・技術情報）のモデル | `claude-haiku-5-5` |
| `RESEARCH_ORCHESTRATOR_EFFORT` | 統括役の考える深さ。`low`・`medium`・`high`・`max` のどれか。深いほど費用がかかります | `medium` |
| `RESEARCH_ORCHESTRATOR_WEB` | `true` のときだけ、統括役も自分でウェブを検索します。ふつうは調査役に任せます | 検索しない |

- 考える深さの指定を受け付けない古いモデルを選んだときは、深さの指定を送りません
- 30 日のデータ保持が必要なモデルを指定したときは、ログに警告を出して既定のモデルに戻します（会議の文字起こしを送るため、データを残さない契約を選べるようにしておくためです）
- いま使っているモデル・考える深さ・統括役が検索するかは、サーバの起動時にログへ 1 行出ます

## 外部に送るデータ

このアプリは、次のデータをサーバから外部のサービスへ送ります。各サービスの利用規約とデータの扱いを確かめてから使ってください。

デスクトップアプリと iPhone アプリは、会議の音声をまず自社のサーバに送ります。外部のサービスへは、サーバから送ります。

| 送り先 | 送るもの | いつ |
|---|---|---|
| ElevenLabs | 会議の音声 | 文字起こしのあいだずっと |
| Anthropic | 文字起こし、要約、補足資料や参加者の情報、会議中のメモ。Gemini が無いときは補足資料や参加者の画像も | リアルタイム調査・グラレコの区切りの判定・アシスタントのとき。Gemini が無いときは要約・議事録・用語解説・画像の読み取りのときも |
| Google Gemini（キーがあるとき） | 文字起こし、要約、会議中のメモ、補足資料や参加者の画像、グラレコの元になる文章、グラレコ検索の言葉 | 要約・議事録・用語解説・画像の読み取り・グラレコ・グラレコ検索のとき |
| OpenAI（キーがあるとき） | 会議の内容から作ったグラレコの作画の指示 | 手動グラレコ・最終グラレコのとき |
| Resend（キーがあるとき） | 宛先のメールアドレス、パスワード再設定のリンク、議事録の本文 | メールを送るとき |
| Gemini か Anthropic（カメラ観察を有効にしたとき） | 約1分ごとに1枚のカメラか画面の画像 | カメラ観察のとき（[room-observation.md](room-observation.md)） |
| 検索で見つかったウェブサイト | ページの取得（サーバが直接取りに行く。開けるのは、その回の調査で検索結果に出たページだけ） | リアルタイム調査のとき |
| Google（Google ログインを使うとき） | ログインの確認 | Google でログインするとき |
| GitHub | 新しい版の情報の問い合わせ（会議のデータは送らない） | `/download` と更新履歴のページを開くとき |

### リアルタイム調査と、ウェブページに書かれた指示

リアルタイム調査では、AI が会議の内容を手元に持ったまま、検索で見つけた第三者のウェブページを読みます。
ページの中に AI への指示が隠して書かれていると、AI がそれに従って、会議の内容を含むアドレスを開こうとするおそれがあります（会議の内容が外へ持ち出される危険）。

- アプリでは、ページを開けるのを、その回の調査で検索結果に出たページのアドレスだけに限っています。アドレスを書き足したり書き換えたりしたものは開きません。組織の中のアドレスも開きません
- それでも、検索の言葉や、検索結果に出たページを開くこと自体から、話題が推測される余地は残ります
- 気になる会議では、会議の画面でリアルタイム調査をオフにするか、`.env` に `RESEARCH_ENABLED=false` を書いてサーバ全体で止めてください

### サーバから外へ出る通信の宛先

サーバの外向きの通信を、許可した宛先だけに絞っている場合は、次を許可します（どれも https の 443 番）。

| 宛先 | 使うとき |
|---|---|
| `api.elevenlabs.io` | 文字起こし（常時接続の WebSocket を含む） |
| `api.anthropic.com` | リアルタイム調査・要約など |
| `generativelanguage.googleapis.com` | Gemini のキーがあるとき |
| `api.openai.com` | OpenAI のキーがあるとき |
| `api.resend.com` | メールを設定したとき |
| `www.googleapis.com` | Google ログインを使うとき（ログインの確認） |
| `api.github.com` | `/download` と更新履歴のページ |
| `<アカウント>.r2.cloudflarestorage.com` | `AUDIT_R2_*` を設定したとき |
| 検索で見つかったウェブサイト（宛先は決まっていない） | リアルタイム調査でページを開くとき |

- リアルタイム調査のページの取得は宛先が決まっていないため、宛先を絞るとページを開けなくなります（検索の結果だけで調査を続けます）。調査ごと止めるときは `RESEARCH_ENABLED=false` にします
- どの場合も、**サーバから組織の中の重要なシステムへは届かないように**、ネットワークを分けておくことをすすめます（次の節）

## 安全のためにすすめること

- **https で公開する**（A か B の方法）
- **`INITIAL_ADMIN_EMAIL` を設定してから立ち上げ、すぐに最初の管理者を登録する**。最初の管理者になれるのは、このアドレスで、サーバのログに出る初期設定コードを入れた人だけです
- **サーバから組織の中の重要なシステムへ、外向きの通信が届かないようにする**。リアルタイム調査では、サーバがウェブページを取りに行きます。アプリ側でも内部のアドレスには行かないようにしていますが、ネットワークでも分けておくと安心です
- **`.env` とデータベースのバックアップを、ほかの人が読めない場所に置く**。キーやパスワード、会議の記録が入っています
- データベース（5432 番）とアプリ（3000 番）のポートを外に開けない。既定の設定では、どちらも外からは届きません

## 新しい版にする

```sh
git pull
docker compose up -d --build
```

A の方法で立ち上げている場合は、`--profile https` を付けます。

```sh
git pull
docker compose --profile https up -d --build
```

データベースの表や列の追加は、立ち上がるときに自動で行われます。念のため、更新の前にバックアップを取ってください。

### 利用者のデスクトップアプリを新しくする

- デスクトップアプリには、自動で新しくなる仕組みはありません。利用者に `/download` から新しい版を入れ直してもらいます（上書きでインストールできます）
- 新しい版の内容は、ウェブ画面の更新履歴（`/changelog`）で見られます
- 管理画面の「お知らせ」で、利用者に更新を知らせられます。お知らせはウェブ画面とデスクトップアプリに出ます
- 古い版を使えなくしたいときは、`.env` に `MIN_DESKTOP_VERSION`（例：`MIN_DESKTOP_VERSION=1.2.0`）を書いて `docker compose up -d` をやり直します。それより古いアプリは接続を断られ、ダウンロードのページを開くよう案内が出ます。iPhone アプリは `MIN_MOBILE_VERSION` です

## バックアップと戻し方

### バックアップ

```sh
docker compose exec -T db pg_dump -U grareco grareco > backup.sql
chmod 600 backup.sql
```

`.env` も一緒に保管してください。`.env` が無いと、バックアップを戻しても同じようには動きません。

### 戻し方

1. アプリを止めます

   ```sh
   docker compose stop app
   ```

2. データベースを作り直します

   ```sh
   docker compose exec -T db dropdb -U grareco grareco
   docker compose exec -T db createdb -U grareco grareco
   ```

3. バックアップを流し込みます

   ```sh
   docker compose exec -T db psql -U grareco -d grareco -v ON_ERROR_STOP=1 < backup.sql
   ```

4. アプリを立ち上げます

   ```sh
   docker compose start app
   ```

## 使うのをやめるとき

1. 残したいデータがあれば、先にバックアップを取ります（「バックアップと戻し方」）。利用者は、マイページから自分のデータをダウンロードすることもできます
2. サーバを止めて、データを消します。**`-v` を付けると、データベース（会議の記録すべて）と https の証明書の保存場所も消え、元に戻せません**

   ```sh
   docker compose --profile https down -v
   ```

3. リポジトリのフォルダ、`.env`、バックアップのファイルを消します
4. 各サービス（ElevenLabs・Anthropic・Gemini・OpenAI・Resend）の管理画面で、このアプリ用に作った API キーを無効にします。Google ログイン用の OAuth クライアントも、要らなければ消します
5. 利用者に、デスクトップアプリ（と iPhone アプリ）を消してもらいます

## 費用の目安（2026年10月時点）

- **会議 1 時間あたり**：文字起こしと要約だけなら約100〜200円。リアルタイム調査とグラレコも使うと約400〜800円（Gemini のキーがあると自動グラレコは最初からオンです。費用を抑えたいときは設定でオフにします）
- **サーバ**：2CPU・メモリ4GB 程度で月に数千円

AI サービスの料金は変わることがあります。実際の金額は各サービスの管理画面で確かめてください。

## 困ったとき

| 起きていること | 確かめること |
|---|---|
| ログインしてもすぐにログイン画面に戻される | https で開いているか。B の方法なら入り口が `X-Forwarded-Proto` を渡しているか。入り口が 2 段なら `TRUST_PROXY=2`。http で直接開くなら `ALLOW_HTTP=true` と `TRUST_PROXY=false` |
| アプリが立ち上がっては止まるのを繰り返す | `docker compose logs app` に出る足りない項目の名前を `.env` に書く |
| `[DB] ensureTables failed` が出る | `POSTGRES_PASSWORD` を最初から変えていないか、英数字だけか |
| https の証明書が取れない（A の方法） | `DOMAIN` が書いてあるか。DNS がこのサーバを指しているか。80 番と 443 番が外から届くか。`docker compose logs caddy` を見る |
| デスクトップアプリや iPhone アプリが繋がらない | アドレスが `APP_URL` と同じか。B の方法なら入り口が `Upgrade` と `Connection` を渡しているか。http のアドレスは組織の中のネットワークのアドレスでしか使えない |
| 画像を送ると失敗する | B の方法なら入り口の `client_max_body_size` が小さすぎないか |
| 機能が画面に出ない | 管理画面の「利用状況」で、その機能に要るキーを確かめる。`.env` を変えたら `docker compose up -d` をやり直す |
| 文字起こしが始まらない・要約や調査やグラレコが出ない | `docker compose logs app` で、そのサービスのエラーを探す。キーの写し間違い（前後の空白など）、残高の不足・チャージや請求先の未設定、利用の上限に達していないかを、各サービスの管理画面で確かめる。キーを直したら `docker compose up -d` をやり直す。「利用状況」と起動時の確認は、キーが書いてあるかしか見ていない（正しいキーかどうかは、使ってみるまで分からない） |
| 外向きの通信を絞っていて、文字起こしや要約が動かない | 「サーバから外へ出る通信の宛先」の表の宛先を許可しているか |
| 最初の管理者の登録で「初期設定コードが必要」と出る | `docker compose logs app \| grep 初期設定コード` で最新のコードを探して入れる。立ち上げ直すとコードが変わる |
| 最初の管理者の登録で「INITIAL_ADMIN_EMAIL でしか登録できません」と出る | 登録するアドレスが `INITIAL_ADMIN_EMAIL` と同じか。書き間違えていたら `.env` を直して `docker compose up -d` |
| `/download` のボタンでアプリが落とせない | サーバから GitHub（api.github.com・github.com）に外向きの通信ができるか |
| メールが届かない | `RESEND_API_KEY` と `FROM_EMAIL` が書いてあるか。`FROM_EMAIL` のドメインを Resend で確認済みか |

解決しないときは、GitHub の Issues で知らせてください（日本語・できる範囲での対応です）。キーやパスワード、会議の内容は書かないでください。
